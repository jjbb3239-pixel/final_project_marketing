# 랜딩·블로그 측정 설계와 성과 비교 기록

작성일: 2026-11-06  
상태: **작업공간 초안 / 로컬 미리보기 검증 / 운영 배포 전**

## 목적과 범위

Meta와 Google 검색 광고, 블로그 등으로 유입된 세션의 랜딩 행동을 분석하고, 소재 또는 랜딩 개선 전후의 CTA 클릭률을 비교한다. 상품 상세페이지 이동과 무료 1강 이동을 따로 측정한다. CTA 클릭은 목적지 도착, 강의 재생, 회원가입 또는 구매가 아니다. Meta와 Google Ads 태그 및 광고 목표는 별도 담당이며 이 문서의 GA4 설계에서 변경하지 않는다.

팀 GTM: `GTM-PLPB9NFW` · GA4 측정 ID: `G-VJPV0LRV8K`.

| 이벤트 또는 지표 | 발생 위치와 시점 | 전송할 주요 값 | 질문 |
|---|---|---|---|
| `page_view` | GA4 기본 페이지 조회 | 페이지 주소, 제목, 이전 페이지, 유입 정보 | 어느 광고나 글에서 어느 페이지로 들어왔는가? |
| `landing_view` | 랜딩 한 페이지가 로드될 때 한 번 | `page_type`, `layout_version` | 어떤 버전의 랜딩을 본 세션인가? 자동 `page_view`와 별개로 버전 분모를 식별한다. |
| `cta_click` | 랜딩의 `.cta` 링크를 클릭할 때마다 | `cta_id`, `cta_location`, `destination_type`, `page_type`, `layout_version`, `cta_url` | 어느 위치에서 어떤 목적지로 이동을 시도했는가? 기존 광고 태그도 이 신호를 사용한다. |
| `blog_cta_click` | 블로그 본문 CTA 또는 하단 관련 링크 클릭 시 | `cta_id`, `cta_location`, `destination_type`, `page_type`, `layout_version`, `article_id` | 어느 글에서 랜딩·무료 강의·상품 상세 링크를 눌렀는가? 기존 광고용 `cta_click`과 다른 신호다. |
| `cta_view` | CTA 면적의 50% 이상이 화면에 연속 1초 이상 보이면 버튼당 페이지 로드 1회 | `cta_id`, `cta_location`, `destination_type`, `page_type`, `layout_version`, 블로그의 `article_id` | 어떤 버튼이 화면에 노출됐는가? 실제 시선·읽음을 보장하지 않는다. |
| `section_view` | 주요 콘텐츠 구간이 화면 감지 범위에 들어올 때 구간당 페이지 로드 1회 | `section_name`, `page_type`, `layout_version` | 어떤 구간에 도달했는가? 실제 읽음을 보장하지 않는다. |
| `scroll_depth` | 랜딩의 스크롤 가능한 거리를 기준으로 25·50·75·90%를 처음 통과할 때 | `scroll_depth_percent`, `page_type`, `layout_version` | 전체 페이지를 얼마나 내려갔는가? 섹션 도달과 별개의 보조 지표다. |
| GA4 참여 시간 | GA4에서 페이지가 활성 상태인 시간을 기반으로 수집 | GA4 기본 페이지·유입 정보 | 어떤 유입과 페이지에서 오래 참여했는가? 집중해서 읽은 시간을 보장하지 않는다. |

버튼을 1초가 되기 전에 클릭하면 `cta_click`은 있지만 `cta_view`가 없을 수 있다. 노출 대비 클릭은 동일 CTA가 **먼저 노출된 뒤 클릭된 동일 세션**을 기준으로 분석하고 전체 클릭 수를 전체 노출 수로 무조건 나누지 않는다.

## 랜딩 CTA와 목적지

| `cta_location` | 위치 | `destination_type` |
|---|---|---|
| `hero` | 첫 화면 | `free_lesson` |
| `intro` | 인트로 | `free_lesson` |
| `reviews` | 수강 후기 | `product_detail` |
| `lecture` | 강의 소개 | `free_lesson` |
| `curriculum` | 목차 | `product_detail` |
| `change` | 가격·변화 구간 | `blog` |
| `apply` | 마지막 신청 | `free_lesson` |

`cta_id`는 `landing_`과 위치값을 합친 값이다. 같은 버튼의 문구를 수정하거나 섹션 순서를 바꾸더라도 식별자는 유지하고, 의미가 다른 새 버튼에는 중복되지 않는 식별자를 부여한다. 카페와 유튜브 링크는 현재 `.cta`가 아니므로 이 설계의 랜딩 CTA 클릭에는 포함되지 않는다. 클릭 목적지는 배포마다 링크를 다시 확인한다.

## 섹션과 스크롤 기준

섹션 식별자는 `hero`, `intro`, `reviews`, `lecture`, `curriculum`, `outcomes`, `community`, `faq`, `apply`다. 페이지의 25%가 특정 섹션을 의미하지 않으므로 섹션 도달과 전체 스크롤을 나눠 해석한다. 영역이 긴 경우에도 도달을 감지하도록 화면의 하단 20%를 제외한 감지 영역과 교차하면 기록한다. 빠르게 영역을 건너뛰어 화면에 표시되지 않은 구간까지 도달했다고 추정하지 않는다.

기존에 보고된 `1_hero`, `2_intro` 등과 새 섹션 ID는 정의가 다르다. 전후 비교 시 버전 및 정의 변경을 기록하며 구간 수치의 단순 연속 비교를 피한다. GA4 향상된 측정의 `scroll` 이벤트는 별개의 자동 이벤트이므로 `scroll_depth`와 합산하지 않는다.

## 블로그 글이 추가될 때

빌드는 `wireframe/blog/` 아래의 새 HTML 파일에도 `tracking-head.inc`를 정확히 한 번 넣는다. 블로그 공통 `tracking.js`는 글 경로에서 `article_id`를 만든다. 예: `growth-stock-checklist.html` → `growth-stock-checklist`, `folder/index.html` → `folder/index`. 같은 글의 경로를 바꾸면 새 ID로 기록되므로 변경 이력에 이전·새 경로를 남긴다.

새 글의 측정 대상 버튼은 `.cta-row` 안의 링크를 사용한다. 이외의 위치에 새 CTA가 생기면 공통 추적 대상에 포함되는지 확인해야 한다. 공통 코드는 블로그 하단의 랜딩 및 공식 강의 링크도 추적한다. 블로그에서 팀 컨테이너를 사용하되 `html`, `awct`, `gclidw`를 페이지별 차단해 현재의 Meta 맞춤 HTML과 Google Ads 전환·링커가 새로 실행되지 않게 한다. 이 차단은 블로그의 모든 GTM 맞춤 HTML 태그에도 적용되므로 나중에 팀이 블로그 광고 태그를 원하면 담당자가 별도로 검토해야 한다. 페이지에 직접 삽입된 외부 스크립트까지 자동 차단하는 규칙은 아니다.

동일 세션에서 여러 글을 본 뒤 랜딩 CTA를 누를 수 있다. 글 → 랜딩 → CTA는 GA4 경로 또는 순차 세그먼트로 확인하며 마지막 글이 전환을 만들었다고 단정하지 않는다. GA4 이탈률은 참여하지 않은 세션의 비율이고, 종료 페이지는 마지막 이벤트가 발생한 페이지다. 외부 강의 CTA 클릭도 블로그 종료로 보일 수 있으므로 CTA를 함께 확인한다.

## 광고 유입과 비교 지표

Meta 광고는 일관된 `utm_source`, `utm_medium`, `utm_campaign`, `utm_content` 규칙으로 캠페인과 소재를 구분한다. Google 검색은 광고 계정의 자동 태그와 GA4 계정 연결을 담당자가 확인한다. 2026-11-06 확인 당시 GA4의 Google Ads 연결 목록은 0건이었고, 광고 계정 자동 태그 상태는 확인하지 못했다. GTM의 Google Ads 태그가 존재하는 것과 GA4 계정 연결은 별개다.

| 지표 | 계산 | 해석 |
|---|---|---|
| 상품 상세 CTA 클릭 세션률 | 상품 상세 CTA를 1회 이상 클릭한 대상 세션 ÷ 같은 대상 랜딩 세션 | 프로젝트의 상품 상세 이동 행동 |
| 무료 1강 CTA 클릭 세션률 | 무료 1강 CTA를 1회 이상 클릭한 대상 세션 ÷ 같은 대상 랜딩 세션 | 무료 강의 관심 |
| 강의 관련 통합 클릭 세션률 | 두 목적지 중 하나 이상 클릭한 중복 제거 세션 ÷ 같은 대상 랜딩 세션 | 두 행동을 합쳐 보고 싶을 때의 참고 지표 |
| 위치별 클릭 | CTA ID별 클릭 횟수와 클릭 세션 | 동일 목적지의 버튼 배치 비교. 횟수와 세션은 별도 |
| 구간 도달률 | 구간에 1회 이상 도달한 대상 세션 ÷ 같은 대상 랜딩 세션 | 섹션 위치·콘텐츠 개선 검토 |
| 광고비 대비 클릭 세션 비용 | 동일 기간·광고 범위의 광고비 ÷ 해당 광고 유입의 강의 CTA 클릭 세션 | 광고 매체 보고와 GA4 세션 기준 차이를 명시 |

동일 기간, 세션 범위, 유입 캠페인, 기기, 랜딩 버전을 맞춘다. 광고 소재·예산·타깃과 랜딩을 동시에 바꿨다면 관측된 변화의 원인을 랜딩으로 단정하지 않는다. 광고비와 세션은 수집 기준과 기간 차이로 매체 보고서와 다를 수 있다.

## 검증 및 미완료 기록

- 로컬 복사본에서 PC 구간 9개, 스크롤 25·50·75·90, 모바일 일부 구간, CTA 목적지 분류를 확인했다. 실제 화면 크기와 변경 후 레이아웃에서 재검증한다.
- 광고 서버 요청을 차단한 로컬 Tag Assistant 미리보기에서 `landing_view`, `section_view`, `cta_view`, `scroll_depth`, `cta_click`, `blog_cta_click` 태그 실행과 주요 매개변수를 확인했다. 블로그 테스트에서는 Meta 픽셀이 로드되지 않았고 블로그 클릭에서 GA4 태그만 실행됐다.
- GA4 전송 요청은 관찰했지만 2026-11-06 확인 당시 DebugView에는 디버그 기기가 표시되지 않았다. GA4의 `Internal Traffic` 제외 필터가 활성화된 사실은 확인했으나 이 테스트의 미표시 원인인지는 확인되지 않았다. **GA4 실제 수신은 미확인**이다.
- 초기 테스트 중 기존 Meta·Google Ads 태그 요청이 발생한 이력이 있다. Meta 광고 귀속 여부는 미확인이다. 후속 테스트는 광고 서버 요청을 차단한 로컬 환경에서 진행했다.
- 팀 GTM 초안 게시, 개선 랜딩·블로그 운영 배포, 운영 URL의 안전한 수신 검증, 실제 비교 수치 입력은 아직 완료되지 않았다. `qa / testing / tracking_check` 테스트 유입은 실제 광고 분석과 구분한다.
